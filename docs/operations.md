# Локальная эксплуатация и подготовка сервера

## Сейчас

Приложение работает локально на `http://127.0.0.1:3000`. Подтверждение email временно отключено: после регистрации или входа доступно рабочее пространство, включая ранее созданные неподтверждённые аккаунты. `/verify-email` перенаправляет в `/workspace`; письма подтверждения не создаются. Для возврата функции задайте `REQUIRE_EMAIL_VERIFICATION=true` после проверки доставки (в Docker — в `compose.yaml`). Это не меняет статус подтверждения адресов в базе. Письма восстановления пароля по-прежнему записываются в `data/mail-outbox/*.json`; в production локальная доставка запрещена.

Восстановление: `/forgot-password` → письмо → `/reset-password#token=...` → новый пароль → вход. Токены хранятся в SQLite только в виде SHA-256, ссылки одноразовые (подтверждение 60 минут, сброс 30 минут). Смена пароля отзывает все сессии. Фрагмент ссылки считывается браузером и убирается из адреса; сервер не получает его в URL. Сканирование ссылки GET не подтверждает email и не меняет пароль — требуется действие в форме.

`/workspace/account` показывает аккаунт и удаляет его данные после ввода пароля и явного подтверждения. `/privacy` описывает реальную обработку данных MVP. Это не финальные юридические условия: до публичного запуска владелец должен добавить свои контакты и проверить условия для своей модели работы.

## База и резервное копирование

- Данные: `data/analymark.sqlite`; можно задать абсолютный `DATA_DIR` до старта.
- `npm run backup` создаёт согласованную online-копию SQLite, включая закоммиченные данные WAL, проверяет `integrity_check` и ограничивает права файла. Живую базу нельзя копировать обычным копированием одного `.sqlite` во время работы.
- `npm run check:restore -- <путь-к-копии>` копирует backup в отдельную временную папку и проверяет целостность и таблицы. Рабочую базу команда не заменяет.
- `npm run maintenance` удаляет просроченные сеансы/токены/лимиты, устаревшие публичные кэши, локальные письма старше суток и копии старше 7 дней в стандартной папке `data/backups`.
- При необходимости реального восстановления остановить приложение, сохранить текущую базу отдельно, восстановить проверенную копию в отдельный DATA_DIR и сначала проверить её там. Автоматической замены рабочей базы нет.
- Локальные копии не защищают от потери диска. До внешнего запуска нужна отдельная внешняя копия с ограниченным доступом. Восстановление старой копии может вернуть ранее удалённые данные; после восстановления следует снова применить известные удаления.

## Подготовленный Docker-вариант

Одна копия приложения на Node 24 + постоянный volume SQLite + Caddy для HTTPS. Горизонтальное масштабирование этой конфигурацией не предусмотрено. Образы не опубликованы, внешний сервер не создавался.

1. Подготовить сервер с Docker Engine и домен с DNS на сервер; открыть 80/443.
2. Скопировать `deploy/compose.env.example` в защищённый файл вне Git, задать DOMAIN, ACME_EMAIL, MAIL_FROM и RESEND_API_KEY. Подтвердить домен отправителя в Resend. Указать собственный OpenAI-ключ и OPENAI_ENABLED=true только если нужен ИИ.
3. Проверить: `docker compose --env-file <секретный-env-файл> config --quiet`.
4. Запустить: `docker compose --env-file <секретный-env-файл> up -d --build`.
5. Проверить `/api/health`, регистрацию и доставку писем с внешнего браузера. Caddy получает сертификат только при подходящем домене и доступных DNS/портах.
6. Контейнер backup делает копию и обслуживание при старте, затем каждые 24 часа. Он ждёт healthy-приложение; ошибки видны в его журнале. Копии хранятся в общем volume и требуют внешнего экспорта.

API-порт приложения не опубликован на хост: доступ идёт через reverse proxy. Добавлены ограничение размера тела, защитные заголовки и ротация Docker-журналов. `/api/health` возвращает только ok без секретов; при ошибке БД/production-конфигурации — 503. Проверка не подтверждает действительность ключей провайдеров или доставку письма.

Состояние проверки на этой машине: `docker compose ... config --quiet` прошёл. Docker Engine не запущен; сборка образа, запуск контейнеров и получение реального HTTPS-сертификата не проверены. Production-сборка Next проверяется отдельно.

## Диагностика и ограничения

Прикладные события пишутся JSON в stdout: фиксированный код, время, HTTP-статус и ID; без паролей, email, текстов, токенов и ответов провайдеров. В контейнерах журналы ротируются. Dev-сервер Next дополнительно пишет маршруты запросов — не передавайте секреты в query string. Публичный мониторинг и уведомления оператору пока не подключены.

Kaspi — публичный недокументированный источник; при изменении формата, количества или неполной загрузке рыночные рекомендации скрываются. Проверки: `node --use-system-ca --experimental-strip-types scripts/check-kaspi-live.mts`, опции `--extra` и `--pagination`. Запросы последовательные, интервал не менее 10 секунд. Скрипт сохраняет только публичные данные товара и анонимные суммы; не запускайте его как массовый сборщик.

Документация: [Node SQLite backup](https://nodejs.org/api/sqlite.html), [Next self-hosting](https://nextjs.org/docs/app/guides/self-hosting), [Resend send email](https://resend.com/docs/api-reference/emails/send-email), [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https).

## Локальный ИИ в feature/ollama-qwen35

Провайдер по умолчанию — Ollama, модель `qwen3.5:9b`. Нужны установленная модель и запущенный локальный сервер Ollama; новые веса без необходимости не скачиваются. Настройки подключения находятся в `.env.local` и `.env.example`; API-ключ не требуется. `AI_ENABLED=false` отключает генерацию. Старый OpenAI-ключ не используется при `AI_PROVIDER=ollama`.

Данные формы передаются только выбранному провайдеру. Для этой ветки проверяется локальный HTTP-адрес, облачные имена моделей не принимаются, редиректы запрещены. Запускайте Ollama с `OLLAMA_NO_CLOUD=1`, чтобы также запретить облачные функции самого Ollama. Приложение не включает доступ к Ollama из локальной сети автоматически.

В Docker `127.0.0.1` обозначает сам контейнер. Шаблон использует `host.docker.internal:11434`; доступность модели на хосте нужно проверить отдельно. Эта конфигурация не разворачивает Ollama в контейнере, не скачивает веса и не подтверждает доступность GPU. Нативный локальный запуск проверяется отдельно командой `node --env-file=.env.local --experimental-strip-types scripts/check-ollama.mts`. Не открывайте незащищённый порт Ollama в интернет.
